## 1. Issues
### Device-memory Capacity (Memory-constrained Environment)
- Growing MoE parameter counts increase the volume of weights
- Long-context agent tasks expand the KV cache 
- Prevent the complete set of model weights from residing in devices memory

### Limitation of Expert offloading
- Retaining inactive experts in host memory -> reducing device-memory demand
- Loading a selected expert after routing places host-to-device(H2D) communication on the inference critical path

## 2. Existing Solutions
### Activation-locality methods
- Use routing traces or semantic history to identify experts that are likely to be reused and retain them in a device cache
- MoE-Infinity and FineMoE

### Auxiliary-predictor methods
- A separate lightweight model to predict expert activations before the original router is reached
- SiDA-MoE and Pro-MoE

### Cross-layer and phase-aware methods
- Obtain expert information from later gates or reorganize transfers according to layer and inference phase
- Fate, Adap-MoE and DuoServe-MoE

### Expert-substitution methods
- Avoid selected transfers in eligible cases by executing an already resident alternative expert
- SMoE and BudyMoE

### Routing-History-Aware Expert Cache (Decode phase, Online)
- RHAC selects eviction victims, but it bases the decision on both activation history and the router scores already produced during MoE inference
  - RHAC is updated per token
  - RHAC maintains four signals for every expert e at layer l (resident-priority score)
    - f: recent selection frequency, how many of the latest W tokens select exeprt e
    - f_bar: long-term selection tendency with an exponential moving average (EMA)
    - q: current router score, provide information about every expert
    - a: age, how many generated tokens have elapsed since the expert was last selected
  - RHAC selectes the coldest evictable resident expert

### Cross-Layer Expert Prefetching (Decode phase, Online)
- MoE-CORE predicts the next layer's expert ranking early and transferse a bounded number of likely experts while the model continuse computing 

### Approximate Expert Substitution (Decode phase, Online)
- MoE-CORE provides an optional approximate expert substitution (AES) path based on the score distribution aroudn the Top-k routing boundary
  - Using score proximity to restrict substitution to low-score routing decisions near the seleciton boundary
